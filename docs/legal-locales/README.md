# 协议国际化维护

## 文本来源

四份根目录中文 Markdown 协议是源文，不在翻译过程中修改其适用地区、责任、退款例外或未完成事项。

本目录的 5 个语言 JSON（简中、繁中、日、韩、英）包含四份完整协议和阅读提示。`zh-Hans` 保留源文；其他目录是机器辅助译文，不等于当地法律适配或逐语言法律审定。页面明确说明译文性质，并提供中文原文切换。App 与 Web 共用同一套语言；App 的其余语言目录统一回退到 `en`。

## 更新流程

1. 更新根目录四份中文协议。
2. 运行 `npm run legal:translate`，离线重新生成译文；可在命令后指定语言，例如 `npm run legal:translate -- ja ko`。
3. 阅读并校订本目录的译文。尤其检查否定、例外、授权、期限、注销、取消续订和退款之间的区别。
4. 运行 `npm run legal:sync`，将这五种语言同步到 App 与 Web。
5. 运行 `npm run check:legal-localization`、`npm run check:compliance`、`npm run check:localization`、App 与 Web 的 Lint、类型检查和 Web 构建。

源文和页面提示共同计算 `sourceHash`。源文变更后，旧译文不能继续同步；同步工具会报错而不是静默展示过期译文。人工校订同一源文的译文时保留其 `sourceHash`。若要对源文改版后的译文作人工更新，应先完整核对该语言的四份协议，而不是只手动替换哈希以绕过检查。

## 翻译与校验边界

翻译工具仅在显式运行时使用公共 Google 翻译入口，发送的是准备公开的协议与界面提示，不发送用户账号、照片或运行时数据。不需要新增依赖或将翻译服务接入 App。临时响应缓存保存在系统临时目录，可以用于断点继续，不进入发行包。

工具保护并检查链接、邮箱、电话、数字、条款编号、段落和强调标记，校验所有目录完整，并保证同语言的双端文本一致。此类自动检查不能证明法律意义或所有语言的语法完全正确，正式发行前仍需要按发行范围作语言及法律复核。

App 只在访问时载入所选语言的本地协议包；Web 使用语言分包。同步源文件不等于已经部署网站或发布 App。
